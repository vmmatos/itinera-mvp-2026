Negotiation Glossary

Terms used across lessons. One definition per term, adhered to everywhere — if a lesson seems to use a word differently, that's a bug, flag it.

Negotiation protocol
The fixed rules for who may say what, when — not what any agent decides to say. A protocol is enforced by the platform; a strategy (what an agent proposes) is up to the agent. itinera: the protocol is WorkflowStateMachine's transition table. Each preference agent's strategy is its persona prompt.
Round
One complete pass of proposal → response across the participating agents. A negotiation is a sequence of rounds until a stopping criterion fires. itinera today: mostly one round per state (no re-announcement). ITINERARY_REPAIR ⇄ FINANCE_VALIDATE is the one place with a real repeat-round loop, bounded by WORKFLOW_MAX_RETRIES.
Manager / Contractor (Contract Net Protocol roles)
Manager announces a task and needs it done; contractors bid to do it; manager awards to one (or several, subcontracted). itinera: orchestrator-agent plays manager during merge/conflict-resolution; the 4 preference agents play contractor during PARALLEL_TURISTIC_PLANNING.
Announce / Bid / Award (CNP's 3 stages)
Announce: call for proposals. Bid: contractors submit offers. Award: manager picks (and may reject all, or ask again). itinera: PARALLEL_TURISTIC_PLANNING = announce+bid (agents run in parallel, no back-and-forth yet); MERGE_AND_SCORE = award.
Soft veto
A participant can object and force reconsideration, but cannot unilaterally kill the deal — contrast with a hard veto/hard block. itinera: finance-agent's budget check. Up to BUDGET_TOLERANCE_PCT over budget is approved anyway; beyond that it triggers repair, not cancellation.
Stopping criterion
The rule that ends a negotiation: consensus reached, round cap hit, or a participant walks away. Choosing this rule is a design decision, not a default to copy blindly. itinera: currently a flat retry cap (WORKFLOW_MAX_RETRIES, default 2) + best-effort ship with overBudget flagged. #42 needs to decide whether that's still right once negotiation gets more rounds.
Re-announce vs. repair
Re-announce: throw out prior bids, run the full announce/bid/award cycle again. Repair: keep the existing award, ask for a targeted edit against it. itinera's ITINERARY_REPAIR is a repair, deliberately — a targeted edit list against the existing itinerary, not a full re-merge (cost: ~8k vs ~170k tokens/cycle per project memory). This is closer to a contract amendment than classical CNP, which doesn't have a repair concept.
